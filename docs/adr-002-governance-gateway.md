# ADR-002: 基于执行守卫与行动化拒绝的治理网关设计 (Governance Gateway & Actionable Refusal)

## 状态 (Status)
**已接受 (Accepted)** - 2026-10-10

## 背景与上下文 (Context)
在多智能体协同与自主工作流执行中，智能体可能因为循环逻辑、Prompt 偏差或异常工具响应而陷入死循环、产生无限工具调用或迅速耗尽 API 预算。
通过对 AgentsRoom 生产级治理架构的逆向分析，我们识别出两大关键治理模式：
1. **前置阻断 (Pre-execution Guardrails)**：必须在产生外部模型费用或执行高危工具之前拦截，而非在事后仅作审计记录。
2. **行动化拒绝文案 (Actionable Refusal Messages)**：大模型遇到报错时本能倾向于“换个姿势重新尝试”。普通的报错提示（如 `Limit exceeded`）会导致大模型反复重试，加剧资源浪费。因此，拦截反馈必须包含明确的行动指引（Actionable Next Step）并明令禁止无意义重试。

## 架构决策 (Decisions)

### 1. 独立治理网关组件 (`GovernanceGateway`)
在 `apps/api/src/governance.ts` 中抽象独立的 `GovernanceGateway`，负责统一管理角色运行额度、工具权限与审计日志：
- **节点执行守卫 (`evaluateAgentExecution`)**：在调度引擎 (`RunEngine`) 执行 Agent 节点前，核验角色的 `maxSteps` 和当前累积 `actualCost + estimatedCost`。
- **工具调用守卫 (`evaluateToolCall`)**：在工具实际执行前，校验工具是否属于角色授权白名单（`role.tools`）、单次运行工具调用次数是否超过 `maxToolCalls`，以及预算是否超限。

### 2. 行动化拒绝文案规范
所有由治理网关拦截生成的错误信息，必须严格遵循“原因诊断 + 行动指引 + 禁止重试”三段式结构：
- **步骤超限**：
  `治理网关拦截：已达到该角色执行步骤上限 (N)。请拆解任务为更小的子流程或调整角色限额配置；请勿重复重试当前节点。`
- **预算超限**：
  `治理网关拦截：预计费用 ($X) 超出该角色预算法定上限 ($Y)。请缩减上下文或提高角色预算配额；请勿盲目重试。`
- **工具超限**：
  `治理网关拦截：已达到该角色工具调用上限 (N)。禁止发起新的工具调用，请直接根据已有上下文生成最终结论；请勿继续重试该工具。`
- **越权工具拦截**：
  `治理网关拦截：角色未授权使用工具 '{toolName}'。仅允许调用: [{allowedTools}]。请调整调用策略或在角色定义中授予权限；请勿尝试伪造或绕过工具调用。`

### 3. 可审计持久化日志 (`mcp-journal.json`)
每一次工具调用尝试（无论是 `approved` 还是 `rejected`）均被标准化记录为 `ToolAttempt` 并持久化到工作区存储目录下的 `mcp-journal.json`。
模式严格校验 UUID、时间戳、入参与花费，支撑事后安全审计与复盘。

## 影响与后果 (Consequences)

### 正面效益 (Positive)
- **防死循环与费用围栏**：从底层阻断了工作流陷入失控调用链导致天价账单的风险。
- **防止 LLM 重试风暴**：行动化拒绝文案有效引导模型停止调用并总结已知信息输出，或者直接报告障碍。
- **零依赖入侵**：引擎与网关解耦，未来可轻松扩展更多自定义策略（如速率限制、动态敏感词阻断）。

### 权衡与代价 (Trade-offs)
- 增加了工具调用和节点执行的前置校验逻辑，但由于基于本地内存与异步原子化持久化，耗时通常 < 1ms，对整体执行延迟无感知。
